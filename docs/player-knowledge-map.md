# 玩家认知与地图解锁

地图不是世界全貌，而是玩家此刻能够说出、定位并前往的地点集合。内部正典、主角既有记忆和玩家已获信息必须分开。

## 三层信息

1. 世界事实：地点真实名称、人物身份、案件真相。只供事实图谱与严格审查使用。
2. 主角认知：主角在设定中可能认识某人，但不能据此跳过面向玩家的介绍场景。
3. 玩家认知：实际在正文中见到、听到或由证据推导出的信息。地图、状态栏、选项与编剧只能读取这一层。

## 地点阶段

- `hidden`：地图不显示，也不泄露隐藏地点总数。
- `rumored`：显示问号和模糊称呼，可查看线索但不能移动。
- `located`：坐标与安全称呼已确认，可以移动。
- `visited`：玩家到访过，可使用更具体但仍不越过身份边界的描述。

阶段由 `knowledgeEvents` 推导，不由轮次数自动开放。旧存档缺少该字段时，程序补入公寓、中学和便利店三个初始地点，并可从已获得线索迁移部分事件。

## 关键解锁链

- 灯织：本人出场、来电或可靠介绍 → 人物简介 → `灯织住的商住楼`。
- 周大爷：本人出场并与玩家交谈 → 人物简介 → `周大爷住的旧楼`。
- 水塔：残页或草图 → `山中的旧设施？` → 路线或证词确认 → `废弃水塔`。
- 赵刚：直接观察 → `寸头男人` → 跟踪或地址证据 → `黔灵旅社` → 证件或登记 → `赵刚`。
- 林静：直接观察 → `陌生女人` → 可靠身份来源 → `林静`。
- 医院：药单、预约或就诊记录使其与当前调查相关后出现。
- 观景台：先听到模糊事故区域，再通过路线或可靠证词确认地点。

## Agent 写入边界

事实守门简报同时携带玩家可见名称和本回合允许触发的认知事件。导演可以为正文计划最多申请一个事件，并写明玩家实际看到或听到的依据。程序审查前置条件；未授权事件不会写入存档。编剧只收到审查后的玩家认知简报，不会看到 `detective-a`、`detective-b` 等内部身份标签对应的正典称呼。

地图移动是确定性程序行为：只有 `located` 或 `visited` 地点可达；抵达后程序写入 `visit:<location-id>`。

## 剧情内介绍与人物页面

人物认知不在整段回复生成完成时提前写入，而是绑定到具体对白行：

```text
对话|old-man|calm|还记得我吗？
对话|旁白|calm|眼前的老人姓周，附近的人都叫他周大爷。
认知|meet:old-man
对话|old-man|happy|雨大，慢些走。
```

第一句播放时，`old-man` 只用于内部选取立绘，说话者标签显示为“？？？”。旁白介绍句播放完成后，播放器才提交导演授权的 `meet:old-man`，随后名称变为“周大爷”，人物简介和住处进入玩家认知，并依次弹出可点击的资料更新提示。

未经导演审查授权的 `认知|event-id` 会在场景解析时被丢弃。快进会按剧情顺序提交被跳过行上的合法事件，避免漏掉已经发生的介绍。

“人物”页面与线索页面相互独立，只展示玩家当前已经接触到的角色。列表显示立绘和当前称呼，详情显示简介与当前已知事实；未知角色不会提前出现在列表中。
