# 核心子界面视觉统一设计

日期：2026-09-01

## 目标

将第一批高频游戏子界面——线索、地图、调查/行动——统一到当前 PC 主界面的低清黑白 8-bit 悬疑视觉体系中，同时保持现有功能、内容结构、数据逻辑和背景读取规则不变。

本阶段只处理 PC 端。手机小屏适配、存档/历史/设置等后续界面，以及业务功能重构均不在本次范围内。

## 已确认方向

采用“共享像素组件 + 各界面独立编排”方案。公共组件只负责视觉、布局、可访问性和基础开合交互；线索、地图、调查/行动组件继续拥有各自的 Store 选择器、业务状态和事件处理函数。

Penpot 评审页：`First Batch / UI Layouts`

Penpot 文件：`漫长的告别 · PC 主界面 UI`

本地可编辑 SVG 草图：`docs/design/first-batch-ui-layouts.svg`

## 设计空间与缩放

- 三个界面进入现有 1672×941 HUD 设计空间，由 `HudViewport` 统一等比例缩放。
- 弹窗和面板使用设计像素定位与尺寸，不分别使用 `vw` 推导宽高。
- 内容区可使用弹性布局和内部滚动，但标题栏与底部操作栏保持固定。
- 背景资源选择、时间背景切换和图片读取逻辑不变。

## 公共组件架构

### PixelModalShell

负责遮罩、设计空间内定位、打开/关闭动画、点击遮罩关闭、Esc 关闭、焦点进入与关闭后的焦点恢复。确认弹窗处于打开状态时，父弹窗不响应关闭操作。

### PixelModalFrame

复用主界面的阶梯切角双层边框。提供普通、强调、危险三种语义状态；语义通过框线密度、网点和图标表达，不依赖彩色。

### PixelModalHeader

统一呈现独立 SVG 图标、中文标题、英文或计数副标题及关闭按钮。标题栏高度、分隔线和关闭按钮尺寸在三个界面中一致。

### PixelPanel 与 PixelListItem

负责内容分区、列表卡片、默认态、悬停态、选中态和禁用态。组件只接收内容与状态，不读取游戏 Store。

### PixelActionButton 与 PixelStatusTag

统一主要操作、次要操作、消耗信息、状态提示与禁用反馈。正式图标必须使用整数像素对齐的独立 SVG，不使用 Unicode 字符代替。

### PixelModalFooter

提供固定底部操作区及左右插槽，用于选择计数、移动消耗、说明文字和主要操作。

## 页面布局

### 线索界面

- 使用居中的大尺寸双层像素弹窗。
- 标题区显示“线索”和 `ORGANIZED CLUE INDEX 当前数/6`。
- 线索列表占据主要内容区；选中项使用白底黑字反相。
- 每项保留选择、来源、描述和删除功能。
- 底部左侧显示已选数量，右侧保留“尝试推理”。
- 空列表只改变内容区，不改变弹窗骨架。

### 地图界面

- 使用同系列的大尺寸双层像素弹窗。
- 标题区显示“地图”、区域名称和当前位置。
- 现有地图素材、地点节点和地图交互区保持不变，仅更换外框、节点状态和排版样式。
- 位置说明、预计时间、体力消耗和“前往此处”保留在固定底部区域。
- 无法移动、体力不足、演出中等状态继续沿用当前业务判断。

### 调查/行动面板

- 保持比完整弹窗更紧凑的浮动面板形态，不改为全屏页面。
- 标题根据当前类型显示“调查”或“行动”，副标题显示可用项目数量。
- 项目列表统一为图标、标题、说明/消耗和序号结构。
- 悬停或选中项使用白底黑字反相；已完成或不可用项目使用灰阶网点。
- 执行项目的现有消息发送、线索整理和物品查看逻辑不变。

## 视觉规则

- 主色仅使用 `#050505`、`#f2f2f0` 和少量灰阶网点。
- 移除第一批界面中现有的蓝色、金色、发光、圆角和现代阴影表现。
- 面板主体使用不透明黑底，保证纯白和高亮场景背景上的辨识度。
- 框体采用较粗外框、较细内框和黑色间隔，切角尺寸与主界面 `PixelFrame` 一致。
- 默认字体为 `RenOuFangSong 16 / 人偶仿宋`。
- 页面标题使用 24–28 设计像素；正文以 16 为基准；辅助信息使用 12–14。
- 默认态为黑底白字，悬停和选中态为白底黑字，禁用态为灰阶网点和降低亮度。

## 动效规则

- 弹窗展开与收回使用 180–220ms、`steps(4, end)` 的阶梯动画。
- 列表状态切换使用瞬时反相，不使用平滑颜色渐变。
- 遮罩不使用背景模糊；显隐不得依赖透明玻璃效果。
- `prefers-reduced-motion: reduce` 下取消位移与缩放，只保留显隐。

## 数据流与错误处理

- `ClueModal` 继续管理线索读取、选择、删除、存档同步与推理请求。
- `MapModal` 继续管理地点可见性、移动估算、体力/时间结算、场景和背景更新。
- `ActionPanel` 继续管理调查/行动内容、消息发送、物品查看和线索整理。
- 公共像素组件只通过 props 接收状态、内容和回调，不导入 `useGameStore`。
- AI 等待、打字演出、移动处理中等禁用条件保持现状。
- 空数据在固定内容区内显示；长内容只滚动内容区。
- 操作失败继续使用现有通知机制，删除继续使用确认弹窗；只统一这些反馈界面的视觉。

## 预计代码范围

- 新增或扩展 `src/components/ui/` 下的共享像素弹窗组件。
- 改造 `src/components/game/ClueModal.tsx`。
- 改造 `src/components/game/MapModal.tsx`。
- 改造 `src/components/game/ActionPanel.tsx`。
- 按需调整 `src/components/system/ConfirmModal.tsx`，使确认弹窗复用同一框体语言。
- 在 `src/styles/globals.css` 中增加有明确命名空间的公共样式，并移除第一批界面的冲突覆盖。
- 像素图标继续放入现有 UI 素材目录，使用独立 SVG。

不重构 Store、游戏循环、地点数据、背景数据或 SillyTavern 数据结构。

## 测试与验收

### 自动化测试

- 为公共组件增加框体变体、关闭行为、Esc、遮罩、禁用态和焦点恢复测试。
- 更新三个业务组件的现有测试，验证视觉重构没有改变事件和数据结果。
- 覆盖线索选择/推理、地图移动、调查执行、空数据和长内容场景。
- 运行完整单元测试、lint 和生产构建。

### 视觉验收

- 在 1672×941 设计画布检查 Penpot 对齐。
- 在标准 16:9 和 1469×1268 窗口截图，验证 HUD 整体等比例缩放。
- 使用深色、纯白和高对比背景分别检查框体、文字和按钮辨识度。
- 逐项比较框体切角、内外框间距、标题栏、图标、列表选中态、底部操作区和开合动画。

## 完成标准

第一批三个界面在视觉上属于当前主界面的同一组件体系；业务行为与改造前一致；所有自动化检查通过；三组目标窗口和白色背景验收无明显错位、裁切、溢出或对比度问题。
