# 当前设计进度与未完成内容

更新日期：2026-07-08

本文档记录《漫长的告别》当前阶段的设计完成度、已实装内容、仍未完成的系统与建议优先级。它用于后续开发交接和版本收束，不替代更细的剧情、行动系统、多真相设计文档。

## 1. 项目定位

当前项目已经从基础视觉小说原型，推进到一个带有 LLM 交互、变量驱动、线索整理、行动反馈和黑白像素胶片 UI 的叙事调查游戏原型。

目前的核心体验目标是：

- 玩家通过剧情、观察、调查、行动推进故事。
- LLM 根据当前上下文生成剧情、选项、变量变化和行动反馈。
- 玩家可以把观察到的发现整理为线索，并在线索界面组合线索进行推理。
- 推理结果反过来影响变量，例如理智值、好感度、怀疑度和调查进度。
- 整体视觉保持黑白像素、胶片颗粒、扫描线、蓝/金色 UI 点缀的风格。

## 2. 当前已完成内容

### 2.1 基础游戏框架

已完成：

- React + TypeScript + Vite 前端框架。
- Zustand 全局状态管理。
- Dexie 本地存档/聊天记录存储。
- 标题页、游戏画面、对话框、选项、动作栏、状态面板、地图、历史、设置、世界书、预设等主要界面入口。
- 基于 SillyTavern 风格的 preset/lorebook/history/final prompt 组装流程。
- LLM 流式返回解析，包括主文本、选项、摘要、变量等结构。
- 基础存档、读档、历史消息、Prompt 检查器等调试/编辑能力。

当前状态：

- 游戏主流程可以启动、进入开场、播放剧情、展示选项、发送玩家输入并获得 LLM 回应。
- 工程构建可通过 `npm run build`。
- 目前仍存在少量非阻塞 warning，主要是 CSS 选择器 warning 和动态/静态 import 混用 warning。

- 标题页已重新设计并接入标题背景、标题 logo、按钮纹理和按钮交互状态。
- 主游戏界面改为统一的黑白像素 + 胶片 UI 风格。
- 自定义像素手指指针已实装，支持普通、可点击、按下、禁用状态。
- 关闭按钮、滚动条、模态框边角等已统一为像素风格。

当前状态：

- 主界面视觉已经基本统一。
- 标题页、对话框、动作栏、观察/调查/行动面板、状态栏、地图、线索弹窗都已经接入当前视觉系统。
- 后台编辑器/酒馆设置相关界面已做最小风格统一，但不是最终完整美术重做。

### 2.3 角色立绘

- 文穗以 `fumi-normal.png` 为尺寸基准，生成了其他表情的 normalized 版本。

- 小屏横屏布局已能显示角色与底部文本框，但仍建议做更多真实设备测试。

### 2.4 响应式适配

已完成：

- 小屏竖屏下对话框高度、状态面板、动作按钮、模态框做了适配。
- 小屏状态面板默认收缩为按钮，点击后展开。

- 模态框增加了移动端安全区、滚动区域和尺寸限制。

当前状态：

- 仍需要在真实手机浏览器上做最终验收，重点检查虚拟键盘、地址栏高度变化、横竖屏切换后的布局稳定性。

### 2.5 变量系统

已完成：

- 新增默认游戏变量：
  - `cycleCount`
  - `stamina`
  - `sanity`
  - `affinity`
  - `suspicion`
  - `investigation`
  - `unlockedClues`
  - `organizedClues`
- `mergeVariables` 支持：
  - 普通变量覆盖。
  - 对象递归合并。
  - 点路径更新，例如 `affinity.fumi`。
  - `unlockedClues` / `organizedClues` 去重合并。
- `createDefaultVariables` 统一创建初始变量。
- `variablesToEndingContext` 将变量同步给结局检查上下文。
- 切换聊天、开始新游戏、开场初始化时会同步变量。
- Prompt 宏替换支持嵌套变量，例如 `{{affinity.fumi}}`。
- LLM 返回 `<vars>` 后，会合并进当前变量，并同步到聊天记录和结局上下文。

当前状态：

- 变量系统已经可以作为剧情、结局、线索和 LLM 推理的共同状态基础。
- 变量含义和数值区间仍需要进一步设计文档化，尤其是 sanity、suspicion、investigation 的具体阈值。

### 2.6 线索系统

已完成：

- 动作栏新增“线索”入口。
- 新增 `ClueModal` 线索界面。
- 观察页面可以解析观察结果中的发现，并展示为可整理线索。
- 观察页面的线索现在必须点击右上角 `+整理该线索` 才会整理；点击线索正文不会误触。
- 已整理线索写入 `variables.organizedClues`，并同步到当前聊天。
- 线索上限为 6 条。
- 超过上限时提示“当前整理的线索过多，请先进行处理”。
- 重复线索会提示已经整理过。
- 线索界面支持：
  - 查看最多 6 条整理线索。
  - 单条删除。
  - 删除前确认。
  - 多选线索。
  - 点击“尝试推理”。
- “尝试推理”会把玩家名、选中的线索、当前 sanity 和推理规则组织成 user prompt 发给 LLM。
- 推理 prompt 要求 LLM 根据线索生成推理剧情，并在 `<vars>` 中调整好感度、理智值、怀疑度和调查进度。

当前状态：

- 线索整理与推理的第一版闭环已经完成。
- 线索候选目前主要来自观察文本解析，规则还比较轻，需要后续与 LLM 输出格式进一步约束。

### 2.7 行动系统

已完成：

- 主界面动作栏包含观察、调查、行动、地图、历史、线索、设置等入口。
- 观察可以展示当前场景观察内容。
- 调查/行动可以根据当前场景的 `investigateItems` / `actionItems` 展示可选项目。
- 点击调查/行动项目后，会进入对应 LLM 交互流程。
- 行动结果可通过 ActionPanel 展示。

当前状态：

- 行动系统已有前端框架和基本交互。
- 还没有完全变成“稳定可设计”的关卡系统，很多内容仍依赖 LLM 和场景数据质量。

## 3. 当前尚未完成内容

### P0：完成核心可玩闭环

这些内容直接决定项目是否能从原型进入可完整试玩版本。

1. 明确变量阈值与剧情效果

   需要定义：

   - `sanity` 高/中/低各自如何影响 LLM 文风、选项、疯狂行动。
   - `affinity.fumi`、`affinity.touko` 对剧情分支有什么影响。
   - `suspicion.self/fumi/touko/occult` 如何触发怀疑、误判或结局。
   - `investigation.psych/crime/occult/science` 如何对应不同真相路线。

2. 稳定 LLM 输出协议

   需要继续约束：

   - `<maintext>`
   - `<option>`
   - `<sum>`
   - `<vars>`
   - `<action>`
   - `<hint>`

   当前系统能解析和合并变量，但还需要更严格地要求模型输出合法标签，减少跑偏。

3. 线索来源扩展

   当前线索主要来自观察页面。后续应支持：

   - 调查结果中整理线索。
   - 行动结果中整理线索。
   - 主线剧情中出现关键线索时自动解锁或提示整理。
   - 每条线索带来源、轮回次数、场景、时间等元数据。

4. 推理结果落地

   当前“尝试推理”已经能发送 prompt，但需要继续实装：

   - 推理成功/失败的判定。
   - 根据推理结果解锁新调查项或行动项。
   - 根据推理结果推进调查进度。
   - 低 sanity 时生成异常行动选项的前端展示规则。

5. 结局触发条件

   当前变量已经同步到结局上下文，但还需要整理：

   - 普通结局条件。
   - 好结局条件。
   - 真结局条件。
   - 坏结局/疯狂结局条件。
   - 结局已见记录如何影响后续轮回。

### P1：完善叙事内容与关卡结构

1. 场景内容补完

   需要为主要场景补齐可观察、可调查、可行动内容：

   - bedroom1 / bedroom2
   - home
   - apartment
   - school
   - supermarket
   - street
   - suburbs
   - black / death scenes

2. 轮回结构

   需要明确：

   - 第 1 轮到第 N 轮的剧情差异。
   - 每次轮回新增哪些线索。
   - 每次轮回文穗死亡方式、地点、时间如何变化。
   - 玩家如何逐步意识到“轮回本身就是凶手”。

3. NPC 固定内容

   需要补完：

   - 文穗的日常与异常台词。
   - 灯织的调查线。
   - 时坂朔的外部调查线。
   - 文穗“影子”或锚点守护者相关内容。

4. 谜题与调查链

   需要把设计文档中的谜题变成可玩的链条：

   - 死亡日志规律。
   - 锚点物品变化。
   - 文穗日记加密/解密。
   - 地点与时间线索拼图。
   - 最终选择分支。

### P2：体验打磨与发布准备

1. 文案编码与显示清理

   部分历史文件或终端输出存在中文乱码显示风险。需要统一确认：

   - 源码文件保存为 UTF-8。
   - 页面实际渲染中文正常。
   - 旧文档如有必要，重新转存为正常 UTF-8。
   - 所有按钮、提示、弹窗、toast 文案无乱码。

2. UI 细节验收

   需要继续检查：

   - 文本是否溢出按钮。
   - 模态框是否超出屏幕。
   - 滚动条是否能在手机上顺畅操作。
   - hover/active/disabled 状态是否清楚。
   - 线索、地图、设置、存档等弹窗是否风格一致。

3. 移动端真实设备测试

   需要覆盖：

   - iOS Safari。
   - Android Chrome。
   - 微信/内置浏览器，如未来需要。
   - 小屏竖屏。
   - 小屏横屏。
   - 地址栏收起/展开。
   - 输入法弹出。

4. 自动化与回归测试

   已有变量合并相关测试，但仍需要补：

   - Prompt 组装测试。
   - stream parser 测试。
   - 线索整理/删除/推理测试。
   - 存档变量恢复测试。
   - 结局条件测试。

5. 发布前性能与资源检查

   需要检查：

   - 首屏资源体积。
   - 字体体积。
   - 图片压缩。
   - GIF 背景性能。
   - 移动端 GPU/内存占用。

## 4. 建议下一阶段顺序

建议下一阶段按下面顺序推进：

1. 先修正文案和编码问题，确保所有中文 UI、prompt、toast、文档都正常显示。
2. 固化 LLM 输出协议，尤其是 `<vars>`、`<action>`、`<hint>` 和线索标记。
3. 把线索系统扩展到调查和行动结果。
4. 设计变量阈值表，并把 sanity/怀疑度/调查进度真正接入剧情分支。
5. 制作第一轮到第三轮的完整可玩内容，形成 20-30 分钟可试玩版本。
6. 再补结局条件、谜题链和多轮回内容。
7. 最后做移动端真机验收、性能优化和发布打包。

## 5. 当前可验收清单

当前版本建议重点验收：

- 标题页按钮、设置入口、新游戏流程。
- 开场对话是否正常进入游戏。
- 对话文本、选项、快进、自动、重开是否能操作。
- 状态面板在桌面和小屏是否可用。
- 观察页面是否能展示线索候选。
- 观察页面是否只有点击 `+整理该线索` 才整理线索。
- 线索界面是否能查看、选择、删除、确认删除和尝试推理。
- 超过 6 条线索时是否正确提示。
- 推理后 LLM 是否根据线索和 sanity 生成合理剧情。
- `<vars>` 返回后变量是否正确合并和保存。
- 小屏竖屏/横屏下立绘、文本框、按钮、模态框是否可正常操作。

## 6. 风险点

- LLM 输出不稳定仍是最大风险，需要 prompt 协议和解析容错继续加强。
- 变量目前有技术基础，但设计阈值尚未完全确定，剧情分支还没有充分利用变量。
- 线索系统已可用，但线索来源和推理后果还需要设计闭环。
- 移动端已做适配，但还没经过足够多真实设备测试。
- 历史中文文档和部分源码显示存在乱码风险，需要统一清理。

## 7. 当前结论

项目已经完成了“可玩的叙事调查原型”的主要界面、美术方向和基础系统。现在最重要的不是继续扩张 UI，而是把核心玩法闭环收紧：

观察/调查/行动产生线索，玩家整理线索，线索推理改变变量，变量推动剧情分支和结局。

只要下一阶段把 LLM 输出协议、变量阈值、线索来源、推理后果和前三轮剧情内容补齐，项目就可以进入第一版完整试玩目标。
