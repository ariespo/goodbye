# 真实模型延迟实测与发布优化

服务：用户提供的 DeepSeek 官方端点，模型 `deepseek-v4-flash`。上下文上限 100,000，单次输出上限 40,000 tokens；未通过降低用户上限提速。

## 测量口径

实测调用实际 `useGameLoop`，包含上下文准备、导演、按策略触发的审查、流式 Writer、协议校验、必要修复、State 和确定性提交。每个样本从独立的第一日存档开始，输入相同：“我在房间里坐下，整理思绪，暂时不调查新线索。”

“可读”计至已批准场景提交完成，不是模型首 token，也不是浏览器首次绘制。测试使用 jsdom；存档磁盘 I/O、后台预规划和清单补全被隔离，因此结果不包含这些开销，也不是完整浏览器交互或多轮游戏的基准。strict 的 State 使用真实模型；本场景没有近期历史，风格检查可在本地返回。

基线和发布版本各按 standard/strict 测三次。模型输出、服务端缓存与网络均有波动，样本量不足以估计 P95 或承诺稳定提速。没有改变审查策略：不同计划可自然触发不同调用数。

## 基线与发布版本

单位：秒。调用数含失败的 HTTP 能力探测。

| 模式 | 基线可读中位数 | 发布版可读中位数 | 基线范围 | 发布版范围 | 基线/发布版首 token 中位数 |
|---|---:|---:|---|---|---|
| standard | 10.908 | 9.641 | 10.701–11.593 | 7.543–10.860 | 6.420 / 4.888 |
| strict | 11.401 | 10.985 | 11.211–13.179 | 9.575–14.752 | 6.781 / 5.532 |

- standard 中位数改善约 11.6%；均值 11.067 → 9.348 秒。但其中一次发布版计划未引入新事实，只需两次模型调用，因此不能把全部收益归因于序列化优化。
- strict 中位数改善约 3.6%；均值仅 11.930 → 11.771 秒，最慢样本反而更慢。这里尚未证明稳定的端到端提速。
- 调用数：基线 standard 为 5/4/4，发布版 2/4/4；strict 两组均为 6/6/6。
- 导演输出 tokens 均值：standard 915 → 605，strict 984.7 → 612.3。减少的是计划中的缩进与冗长表达，字段与审查路径保留。
- 发布版六次均提交成功，无正文修复、无 HTTP 400。

## 根据实测实施的改动

1. 官方 `deepseek-v4-flash` 的 JSON Schema 请求实际返回 400：`This response_format type is unavailable now`，JSON Object 成功。该精确端点/模型直接采用 JSON Object，代理和其他模型继续能力探测。JSON 解析、确定性校验与语义审查仍然执行。
2. 发给 Agent 的结构化上下文改用紧凑 JSON。回归测试验证反序列化后的上下文和事实简报完全一致。
3. 导演输出要求紧凑 JSON，目的/意图使用短语，描述只写动作与必要因果；仍保留必需字段、来源、认知依据与场景契约。
4. Writer 和两类修复共用输出协议。默认情况下去除旧版要求 Writer 输出状态变化与 timeCost 的指令，明确行指令、至少两个选项和空 vars。自定义格式保留，状态权限限制最后再次声明。
5. 对实际出现的衣柜空缺扩写问题，明确授权线索保留事实原文，氛围级异常不得补出尺寸、类别、成因、行为者或意图。审核仍可拒绝，不将提示视为事实保证。
6. 修正遗留 CSS 测试工具对 CRLF 换行的处理；默认测试排除嵌套工作树与临时诊断目录，避免重复运行旧检出中的测试。

## 迭代证据与限制

共记录 26 个有效配置下的真实回合：先导 2 次、基线 6 次、两组中间版本各 6 次、发布版本 6 次。全部最终提交成功；先导 strict 和第一组中间版本 standard 各有一次正文审核修复。中间版本未稳定提速，保留这些记录以避免只展示最佳样本。最早搭建测试夹具时遇到的 Node/jsdom AbortSignal 不兼容和缺少生产默认格式配置已修正，其结果不进入产品延迟比较。

精简后的可复核数据见 [2026-09-13-live-latency-data.json](./2026-09-13-live-latency-data.json)，含每次调用状态、输入字符量、服务端返回的 token 用量和完整阶段耗时，不含密钥、请求正文或生成正文。流式接口没有完整计费数据时，不推算总费用。

复现：在本地进程环境设置 `DEEPSEEK_API_KEY`、`LIVE_AGENT_BENCHMARK=1`、`BENCH_REPEATS=3`，运行 `npx vitest run scripts/live-agent-latency.test.tsx`。普通测试默认跳过真实模型调用。原始诊断只保存在 Git 忽略目录 `.codex-test-tmp/`。

先前的五项可靠性修复和 40k/100k 默认配置随本次发布一并纳入；详见 [可靠性修复记录](./2026-09-13-reliability-fixes.md)。

发布前验证：`npm test -- --run` 为 671 通过、2 项需显式启用的真实模型测试跳过；最终真实模型组为 6/6 通过。`npm run build`、`npm run lint` 与暂存差异检查通过。独立只读复核未发现新增的权限或协议问题。
