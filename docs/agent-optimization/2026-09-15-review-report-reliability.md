## 原始证据与根因

基线为 `8b148f3`，保留此前已完成的写作规范适配。失败样本来自固定版本 `946ce32` 的 `audit946ce32-g37juice` 活动；19 次尝试中 7 次失败的原统计不追溯改写。逐回合结果见 [原验收记录](2026-09-15-action-intent-acceptance.md) 和 [脱敏证据](2026-09-15-audit946ce32-evidence.json)。

进一步逐条检查原始请求和响应，按最终阻断原因可分为四类：

| 次数 | 尝试编号 | 实际根因 | 本次处理 |
| --- | --- | --- | --- |

13、16 的请求并未显示正常输出预算耗尽；16 的两份损坏报告逐字相同，finishReason 为 stop。因此没有通过扩大 token 上限掩盖结构问题。

该网关曾拒绝完整 schema 内的嵌套 additionalProperties，既有适配已经按具体 schema 回退到 json_object。简化的其他 Agent schema 仍能使用 json_schema。本次没有全局降级模型，也没有删除严格 schema 边界；在回退模式下仍向模型提供相同的完整输出要求。

## 执行和权限边界

- 正常路径仍只有原来的正文审查调用，不增加独立 Skill、审查 Agent 或润色调用。
- 只有不合法报告使用已有的一次纠正，第二次仍失败则保留待审稿并报错；真实行动或事实违规继续走编剧修复。
- 行号只替代引文抄写。每个行动阶段仍须完整覆盖，pass 需非空真实行号，语义是否充分由审查者判断；程序中的 fail 无法被顶层 approved 覆盖。
- 老的 quote 报告仍使用严格逐字匹配；辅助审查不新增行动覆盖要求。
- knownFactSpeakers 只授权复述精确已知层级，受当前可用投影、角色知识上限、禁止 NPC 和饱和转移限制；旧包未提供权限时保持保守行为。
- 听众、跨场景频道、承诺、来源语义、未获准事实及失败不提交状态的规则保持生效。

## 验证

全量 1,433 项本地测试通过，原有 4 项付费测试默认跳过；lint、生产构建及两次独立代码复审通过。新增行动引用、精确权限交集、字段错层、损坏 JSON、schema 回退、合并反馈、辅助兼容的回归；关键故障先复现失败，再验证修复。正常成功只调用一次、第二次报告仍错误就停止、真实 fail 不提交等回归继续通过。

新增 `scripts/live-review-reliability.test.ts`，默认跳过。只读 dry-run 成功提取全部七个末次失败候选，不发送请求；六个样本通过原 Director brief 与已批准计划重建程序发言权限，18 的旧 brief 无法匹配执行后计划，因此保留原包且不增加权限。它不重写正文、不调用编剧、不提交游戏状态。每样本最多 3 次 HTTP、120 秒，整个活动最多 21 次 HTTP。

2026-09-15 的真实复测使用相同网关与模型。已落盘的 6、7 两个样本均未取得有效审查报告；包含连接超时，以及 API 层从 HTTP 200 包装响应中识别出的 HTTP 503 代理错误。人工停止继续消耗，原样保留 [中断证据](2026-09-15-review-reliability-live-evidence.json)，没有把采集脚本运行成功当成剧情获准。中断前的在途请求未全部落盘，因此不提供完整费用或请求总数；测试器随后改为每次请求前后立即保存。

两个样本的首次 system+user 输入分别从 45,018 / 45,029 字符变为 44,837 / 44,848 字符。这仅说明提示体积没有明显增加，不代表精确 token、费用或速度改善。错误响应中的 usage 来自网关估算。

本次已验证程序修复与本地边界，但真实模型通过率仍待网关恢复后重测。固定候选复测本身也只覆盖审查阶段，不等于重新完成全天游戏；不能据此宣称 7 次失败已在真实运行中全部消失。

用户随后要求继续真实复测，并允许换模型验证流程。替代路由的完整结果及发现的残留见 [后续真实复测](2026-09-15-review-retest.md)：六稿最终获准，一稿仍因报告错误失败，另有三稿存在语义漏审。上文保留首次中断活动的历史记录。
