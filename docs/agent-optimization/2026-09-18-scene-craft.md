# 场景创作、按需审查与正文局部修复

## 本次行为

- Director 在现有调用中可选择写作重点、读者感受方向及对应节拍。程序据此提供一个具体场景目标、表现方法和两条小型范例。可选方向包括把不确定感收束为具体问题、克制的摩擦、有边界的关照、短暂缓和与保留待核实问题。
- 这些信息只指导写法，不是事实来源。未提供新字段的旧计划仍可使用；中断、纯旅行或未获得预期结果时，按实际执行内容重新选择指导，不提前演出后续场景。
- standard 始终做程序重复检查，只有疑似近似重复或关键场景才调用文风模型。strict 保留语义检查。旧接口明确关闭模型文风审查时仍执行程序检查。
- State 的最后决定使用已经通过审查的实际正文与证据。只有无互动、无证据或认知变化、无反思/整理线索、无特殊事件，且完整审查证明只是旅行、等待或休息时才省略。缺少有效审查、情况不明确或 strict 时保留调用。资源与时间继续由原事务结算。
- 可准确定位的问题优先尝试一个小窗口，最多三处文字。模型只返回目标编号与替换文本；其他文字、协议、人物、情绪、道具、认知事件保持原样。相邻问答可以一起修，但未出错邻句允许不改。
- 无法定位、范围过大、依赖道具指令、缺少行动或结构错误时使用完整场景修复。非法局部响应消耗原有三次修复预算中的一次，随后退回完整修复；没有另加修复循环。
- 任何模型修复后都重新检查完整正文的协议、事实、行动与角色连续性，再决定 State 和存档。修复前的审查结果不能代替修复后的验收。

## 验证

基线为 1684 项通过、6 项外部接口测试跳过。新增测试覆盖创作权限、场景中断、请求跳过和严格模式、时间/资源结算、局部修改边界、无效响应回退，以及修复偷偷新增事实时禁止状态提交。最终检查为 1734 项通过、7 项外部接口测试跳过；构建与静态检查通过，独立代码审查通过。

独立审查发现并修复：严格输出 schema 必须允许模型拒绝局部窗口；相邻原文必须可以在长度和字符限制下原样返回；带道具的相邻问答应直接退回完整修复。
