## 首轮真实小样本

代码固定为 `774f3a8`，使用已获允许的 `gemini-3.7-flash【神秘】`，重放原第 7、10、16 稿。固定候选与权限输入，不运行编剧、不提交游戏状态。

3 稿均返回可解析报告、完成编号校验，均未触发报告纠正。第 7 稿的“摇了摇头”由程序准确回填；第 10 稿保留 F002 与门卫发言权限，未登记无证据听众。共 4 次 HTTP：一次 schema 400，三次成功生成。

但 schema 400 同时拒绝了 `additionalProperties` 和 `const`；错误消息经过 JSON 转义，未被首版关键字检测识别，实际回退到 `json_object`。因此不能把首轮记录算作 schema 适配成功，需修正兼容检测后再验证。

随后修正：识别 JSON 包装的错误消息，一次汇总明确被拒绝的关键字；布尔 `const` 在传输中省略、仍由原始 schema 本地校验，字符串 `const` 可转为单值 enum。同端点/模型的新补丁 schema 复用已观测的能力。没有增加报告纠正上限。旧版 Gemini response_schema 的 enum 面向字符串，因此没有把 `const: true` 盲目改成布尔 enum。（[Google Schema 说明](https://ai.google.dev/api/generate-content#Schema)）

语义质量仍有局限：第 16 稿将“肯定会有正式身份确认和询问”判为 ordinary-present，无来源，仍属漏审；第 7 稿部分“无新消息/无新收获”也引用了不能直接支持该结论的来源。通过结构检查不代表事实判断正确。

本轮样本少、替代路由且只重放审查，不能换算为新失败率，也不能代表完整自然日游戏已通过验证。
