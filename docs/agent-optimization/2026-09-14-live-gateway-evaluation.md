# 新网关真实模型连续一天评估

本次使用用户提供的新网关补完上一轮因 DeepSeek 余额不足而中断的最终玩法复验。实际可工作的路由是 `https://oneapi.hakoyu.com/v1` 的 `gemini-3.7-flash【神秘】`。这是网关返回的模型标识，未独立验证底层模型身份。

**结论：日终闭环可以完成，但剧情仍有明显拖沓，事实审核和叙事—状态一致性仍有漏检。换成可用模型后能够继续生成，不等于游戏质量已经全部修好。** 本报告对当前玩法的结论优先于 [上一轮因余额中断的复测](2026-09-13-day-fixes.md)，不把早期诊断模式结果混入当前统计。

## 方法与证据边界

- 玩法引擎基线为 `7feb23b5c0ec53b71f14acda9f76e46eb453b396`。本轮新增网关错误分类、采集配置和报告，没有中途修改剧情、时间、状态、审核规则。部分采集过程与网关兼容修复重叠，因此不声称测试了同一个不可变构建二进制。
- 两条轨迹均从正式自动开局开始，调用真实 `useGameLoop`、真实模型 API、正式历史和状态事务。模式为 `standard`；事实、文风、State 等生产校验全部开启，没有观察放行或诊断提示词绕过。
- 快速路线反复输入愿意花接下来两小时搜索或等待；点选路线持续选择模型生成的第一个选项。它代表一种机械点选策略，不代表有经验玩家会采取的所有调查选择。两条轨迹都是第一轮回，不涵盖文穗本人长对话或第 3→4 轮回。
- 存储 I/O 使用测试替身，台词播放即时推进，日终使用实际结算/重置函数。没有模拟真人阅读、思考、鼠标操作、浏览器绘制或 IndexedDB 写入延迟。两条采集有一段时间并行运行，可能影响网关排队与响应时间。
- “有效回合”指成功生成并提交的一次游戏行动；失败后重试另计尝试次数；模型请求还包含后台预规划、检查和修复。三者不能互换。付费测试自身显示通过，只代表采集器完成；真正走完一天以 `completed-calendar-day` 和实际重置为准。
- 逐回合时间戳为 UTC，游戏本地时间加 8 小时。午夜后重回 **9 月 9 日 08:00**，不是进入 9 月 10 日。样本没有因体力/理智提前重置来冒充完整一天。

两条可用路由轨迹合计 **72 个有效回合、79 次尝试、570 次请求发起**。7 次未成功提交均在报错中记录 HTTP 401，随后同一路由重试恢复；其中部分 401 出现在审查阶段，整轮会回滚而不是播放未审文本。请求级日志共 9 个 HTTP 401，另外还有未取得 HTTP 状态的错误；请求失败数不等于游戏回合失败数。两个“果汁”路由另有 2 次完成的失败尝试、6 次已留档请求发起，不混入成功路由的 570 次统计。

若仅做量级估算，按每分钟阅读 400–700 个台词字符，台词阅读约需 7.7–13.4 分钟／21.5–37.5 分钟。再加前台等待约为 **16.7–22.5 分钟／42.3–58.4 分钟**；这是人为阅读速度假设，排除了开局、选项阅读、思考、操作等，不是实际玩家游玩时长。后台等待可能与阅读重叠，不能再整段重复相加。

上述区间只是两条完整路径的实测跨度，样本量不足以估计“普通玩家 90% 会落在什么范围”。没有在这里混用旧版本或撤掉文风审核后的 10–56 回合结果。

延迟以 `playableMs` 为主：从开始处理输入，到正文完成审查并能提交播放。`firstTokenMs` 是内部取得 Writer 首 token 的时间，玩家此时未必能阅读。阶段可能并行，不能将所有阶段时间简单相加。包含后台的累计耗时来自逐次尝试计时，不包含全部测试初始化和真人阅读时间。

快速路线的成功回合共出现 4 次 repair 阶段，点选路线出现 9 次。样本请求总量明显多于“standard 只需 2–3 次调用”的早期估计。当前成功路径保留 Director、Writer、事实审查、文风审查和 State，另有预规划、计划审查、修复及场景检查，不能用最短理论路径解释完整一天成本。

网关 usage 仅在部分响应中被采集；流式响应未统一提取 usage。数据中的 tokens 是**已报告响应的合计下限**，不是完整消耗，更不是账单。没有据此估算金额。

## 日程推进与剧情节奏

**快速路线也并不总是快速。** 前六个有效回合多数只推进 25–30 分钟，虽然输入允许花两小时；第七回合才实际推进 120 分钟。玩家没有指定地点，模型反复描述在雨中寻找、查看手机和等待回复。输入中的两小时是愿意投入的上限，不要求每轮机械耗满，但多次短推进又没有新增发现，会产生明显磨回合的体验。

快速路线第 12 回合推进到 16:00 并挂起死讯事件，第 13 回合推进到 16:20 并明确告知文穗死亡，理智由 70 降到 58。第 15–22 回合多次复用暴雨、崩溃、家人羁绊的段落结构。即使没有大段逐字复读，信息增量仍很低，现有文风审核没有阻止这种语义重复。

**点选路线出现循环调查和长时间空等。** 白天在学校、便利店、灯织之间反复询问、打电话，许多回答只是“没有回复/不知道”。第 30 个有效回合推进到 16:20，第 31 回合完成死讯送达；后续去派出所、询问遗物，继而进入反复坐长椅等待。模型持续把相似等待作为第一选项，机械点选策略进一步放大了这一问题；不是玩家自由输入主动要求每轮重复同一情绪描写。

两条完整日最终的正式线索状态都只有 `shared-apron-missing: atmosphere`。点选轨迹增加了见人、到访、人物印象等知识事件，但这些不等于推进核心证据链。不能据此说“所有玩家都找不到线索”，但作为模型自己提供的默认第一选项路径，它的调查回报偏低。

## 生成与校验问题

| 问题 | 实际证据 | 影响与判定 |
|---|---|---|
| 新增未经授权的精确时间线 | 点选尝试 15／有效回合 14，便利店店员说清晨六点半前后有白色配送车送面包牛奶；对应 WriterPacket 的 authorizedFacts、authorizedBackgroundFacts、approvedBackgroundFactProposals 均为空，已有正式事实仅 F001；此前已接受正文没有这条配送时间 | 事实审核放行了可被玩家当成调查依据的新细节。没有写入正式线索图，不代表正文不会误导 |

这批样本中没有接受空台词回合、没有接受零分钟回合；日终确实返回下一轮早晨。它们证明上一轮的一部分流程修复有效，不证明上述叙事一致性问题已经解决。

## 人物设定能否保持

可观察到的基础称呼与行为倾向大体稳定：便利店李哥有紧张、结巴、冒汗和劝人吃东西的表现；灯织学姐使用“李明”等既有称呼，表现出冷静、保护或指引；老头较亲切，门卫坚持进入学校的限制。样本中没有观察到角色身份突然互换或直接宣布真凶。

但“稳定”也表现为重复口头习惯、动作和功能性劝告。人物没有明显换人，并不等于对话自然、有记忆、会随着玩家调查推进。未经授权的车辆时间、消息状态也会让人物像是临时编造证词。只能判断**本次第一天接触到的角色基本形象尚可维持，长程事实一致性不足**，不能对文穗本人、隐藏动机、后续轮回或全部结局作通过承诺。

**新网关这次的主要失败不能解释为旧 DeepSeek 账户欠费。** 旧网关曾明确返回 402 Insufficient Balance；本次观测主要是上游 503 和间歇 401。401 的根因尚未确定，同一密钥的模型列表和后续游戏请求能成功，不能推断密钥永久失效。

已修复 API router 对完整代理错误包装的识别：HTTP 200 中的代理错误不再被当成正常导演 JSON；流式和非流式均按包装里的实际状态归类，适用既有重试策略。只有完整特征包装才触发，普通正文提到 HTTP 503 不会被误判。流式潜在错误前缀先缓冲，普通正文前缀一旦不匹配立即继续输出；完整代理错误不作为正文播放。网关忽略 stream:true 而返回 JSON 错误的情形也有回归。

评估脚本增加可配置端点/模型/环境变量密钥、记录模型来源、代理失败停止条件。密钥不写入源码和报告。修复不能使已不可用的上游模型变得可用；它改善错误识别，避免无意义的剧情修复消耗。

## 后续修复优先级与验收建议

1. **先约束调查事实与地图状态。** 对精确时间、人员行踪、车辆、通信状态等可调查断言要求授权来源；未知 location 不能直接进入正式地图状态。回归使用本次真实漏检文本，避免只测抽象假例。
2. **对齐叙事、时间和资源。** 将可结算时长传给写作并校验关键时长表达；不得一边描写资源耗尽，一边保存满体力。不能只增加扣资源正则，否则可能误伤情绪化措辞。
3. **改进推进与选项质量。** 连续若干轮没有新发现、行动结果或剧情变化时，应引导到有回报的行动或合并等待。重复氛围不应占据多个完整回合。具体阈值需回放验证，不能用盲目大幅跳时间破坏调查机会。
4. **扩展真实覆盖。** 在同一模型和版本上补目标明确的调查路径、文穗本人长对话、下一轮记忆使用及第 3→4 轮回，至少重复多条随机样本。当前两条完整日只足以确认闭环、给出观察跨度与发现问题。

本轮发布只包含已验证的网关兼容修复及评估工具/报告；本节列出的剧情质量问题仍未修复，未把它们包装成“全部优化完成”。
