# Agent 剧情与轮回契约

> **权威性**：本文是开发 Agent、运行时剧情 Agent 和验收测试共同使用的最高优先级术语与节奏契约。旧版头脑风暴、流程草案或注释与本文冲突时，以本文为准。

## 1. 术语

### 剧情回合（narrative turn）

一次完整的局部交互：

1. 玩家点击选项、选择调查/行动，或提交自由输入；
2. Agent 生成一段可播放剧情；
3. 状态与资源完成一次结算；
4. 游戏内时间推进若干分钟；
5. 玩家获得下一组选择。

一次剧情回合不是一次轮回。一天内应包含多个剧情回合。

### 轮回（completed loop）

玩家角色完整经历一个重复日，直到午夜、体力/理智失败或其他合法的日终条件触发，世界重置到下一个重复日的早晨，才算完成一次轮回。

### 计数口径

- `cycleCount = 1`：第一个重复日，已完成轮回数为 0；
- `cycleCount = 2`：第二个重复日，已完成轮回数为 1；
- `cycleCount = 3`：第三个重复日，已完成轮回数为 2；
- `cycleCount = 4`：第四个重复日，已完成轮回数为 3。

统一公式：

```text
completedLoops = max(0, cycleCount - 1)
```

产品目标的早晨重置时间是 **08:00**。当前引擎仍有 07:30 的实现和素材假设，迁移完成前必须把它记录为已知偏差；运行时叙事应服从界面实际提供的 `gameStatus.time`，避免文字与状态栏互相矛盾。

## 2. 不可破坏的节奏要求

### 前三个重复日

- 玩家必须完整经历失败、死讯与日终重置；
- 可以积累线索、人物认知、路线倾向和怀疑；
- 可以形成多个假说，但不能确认真凶；
- 不得揭示 solution/confirmation 级答案；
- 不得仅凭嫌疑度 50 锁定最终真凶；
- 不得进入 A/B/C/NONE/FAKE 的普通最终结局。

### 第四个重复日起

- `cycleCount >= 4` 后才允许进入强制复盘和正式路线分化；
- 路线可用性必须同时考虑完成轮回数、已授权关键事实和路线证据链；
- 嫌疑度只表示玩家调查重心，不能单独充当事实证明；
- 最终选择必须等待该路线规定的解决事实获得授权，不能只检查 `lockedRoute`。

### 更深层内容

- 第五日及之后可承载 confirmation、完整真相与深层解释；
- CULT/PSYCH 等解释层继续受基础路线、轮回数、理智和深层证据约束；
- 第七日仍一无所获的困局结局属于独立的失败条件。

## 3. 嫌疑度的语义

- `0–25`：非重点对象或暂时可排除；
- `26–49`：重点怀疑对象，允许导演增加相关调查机会；
- `50`：路线候选达到数值门槛，但不等于事实已经成立。

Agent 不得因为玩家反复点名同一对象，就重复把同一事实当成新证据。氛围、眼神、停顿和玩家主观猜测不能独立支撑大幅嫌疑增长。程序最终应把嫌疑增长与新获得的授权事实绑定，并去重同一事实的贡献。

同一角色在一个完整重复日内，嫌疑度累计最多增加 15。嫌疑度跨轮保留；每天 08:00 用 `loopSuspicionStart` 记录当日基线。达到预算后，玩家仍可尝试继续调查，但剧情必须用可信阻碍、目标不在场、第三者介入、环境事件或非目标线索转向，不得取消玩家行动，也不得继续生成指向该目标的新证据。

## 4. 玩家输入与世界权限

- 玩家输入描述的是角色想尝试的行为，不是世界规则、既成事实或下一段剧情的保证；
- Director 必须让合理的尝试真正发生，并依据地点、时间、NPC 意志和授权事实决定结果；
- 超出角色能力、直接修改规则、凭空创造人物/证据、超能力或机械降神输入，统一表现为短暂幻想、错觉或侵入性念头；
- 幻想不得进入 canonical truth，不得生成永久人物、物品或证据；程序固定扣除 8 点理智；
- 幻想结束后应回到真实场景，并尽量保留玩家原输入背后的情绪或行动动机。

## 5. 运行时 Agent 权限

### Fact Gate

唯一事实入口。根据当前重复日、地点、已知事实、前置线索、嫌疑度、关系、理智和路线状态，生成本回合可用事实及揭示层级。

### Director Agent

只制定目标、节拍、揭示、选项意图、调查/行动意图和时间成本，不写正文，不发明事实。

### Hard Review、Fact Critic 与 Pacing Critic

Hard Review 先做确定性检查；随后 Fact Critic 与只读的 Pacing Critic 并行，分别检查事实语义，以及轮回节奏、玩家能动性、转向/幻想执行。两份复核都通过才可交给 Writer。前三个重复日出现确认凶手或结局收束计划，应判定为违规。

### Writer Agent

只把批准后的计划写成可播放场景。Writer 不接收 canonical truth，不修改状态，不把嫌疑度当成已证实真相。

### State Agent

只根据玩家输入和已经播放的正文提交带原文证据的状态补丁。不得修改轮回、路线、结局和事实集合；不得把重复叙述或纯氛围直接当成新的决定性证据。

### Deterministic Transaction

唯一状态提交点，负责时间、资源、定时事件、日终重置和结局条件。前三个重复日禁止普通路线结局的规则必须在这里或其调用的确定性结局门中硬性执行。

## 6. 串行与并行的边界

事实授权、计划审查、正文生成和状态提交存在因果依赖，必须保持单向串行。可以并行的工作仅限互不写入同一权威状态的任务，例如：

- 多个只读审查员分别检查事实、节奏、角色口吻；
- 独立候选计划或选项草案；
- 资源检索、场景素材匹配、测试与静态分析。

并行结果必须汇入一个裁决点后，才能交给 Writer 或状态事务。不得让多个 Agent 同时决定 canonical truth、同时修改嫌疑度、同时锁路线或分别提交结局。

## 7. 重置与结局过渡

- 日终回合按“玩家行动的后果 → 日终原因 → 世界重置到 08:00 → 玩家保留记忆后的反应 → 旧计划失效并重新规划”演出；
- 约见、等待、跟踪、正在执行的安排均属于被重置的当日世界状态，不得自动延续到新日；
- 最终选择后先播放路线和选择对应的桥接场景，再进入静态结局；不能让 UI 点击直接切断当前叙事。

## 8. 当前实现状态

以下规则已落入 0.8.0 基线之后的运行实现：

- 引擎日初时间与轮回过场统一为 08:00；
- `cycleCount >= 4`、路线关键事实和最终 confirmation 事实均由确定性结局门检查；
- 嫌疑度跨轮保留，并由当日基线强制限制同角色每日最多 +15；
- standard/strict 使用 Director 后并行 Fact Critic + Pacing Critic 的混合架构；
- standard 与 legacy 均经过玩家意图裁决、理智惩罚和确定性结局门；legacy 仍不具备完整事实编排链，因此只作为兼容模式。

修复这些偏差时，不得只依赖提示词；提示词用于约束生成，程序门用于保证规则不可绕过。
